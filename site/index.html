Forms as code. Workflows built in.

openforms is an open-source, self-hosted form platform for developers — an alternative to Typeform and Tally for teams that want their forms in git. Define forms and their review workflows as YAML, push them with a CLI, and collect and triage submissions from a real admin UI.

Run it in two minutes View on GitHub Read the docs
docker compose 
git clone https://github.com/openforms/openforms && cd openforms
docker compose --profile app up -d --build

open http://localhost:8080/demo    # guided demo
open http://localhost:8080/admin   # admin inbox (demo1234)
open http://localhost:8025         # Mailpit catches every demo email

What you get

One Python process (FastAPI + SQLAlchemy) with the web UI inside, backed by PostgreSQL.

📄

Forms as code

Forms and workflows are YAML or JSON files. openforms push deploys them; openforms pull --check catches drift in CI.

🔀

Submission workflows

Every form can have a state machine with custom states, role and required-field guards, and actions that run reliably in the background with retries.

🔌

Headless first, hosted too

Use the REST API, the TypeScript SDK, the React renderer, or share a hosted page (/f/<slug>) and embed it anywhere with two lines of HTML.

🗂️

A real admin UI

A reviewer inbox, submission timelines, and visual editors for forms and workflows — no separate dashboard app to run.

⚡

Actions with retries

Webhook, email and auto-assign actions are written to a Postgres job queue in the same transaction as the state change: never fired on a failed transition, always fired (at least once) on a committed one.

📦

One container

A single Docker image ships the API, the job worker and the built web UI. Add PostgreSQL and you're running in production.

A form and its workflow

Everything is a file. Validate offline, then push.

openforms validate && openforms push

Architecture

One process handles the hosted pages, the admin UI, the API and the workflow engine; a background worker drains the job queue.

Running it

The full reference lives in RUNNING.md. The short version:

CommandWhat it does
docker compose --profile app up -d --buildFull stack: Postgres, Mailpit, openforms — seeded demo included.
docker compose up -d postgres mailpitDev services only, run the server from source with uv run openforms serve.
make e2eFull stack + Playwright end-to-end tests.
docker compose --profile app down -vStop everything and remove the database volume.
